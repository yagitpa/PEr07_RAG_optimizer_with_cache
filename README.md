# RAG-ассистент с кешированием и замером времени

Учебный проект: минимальная RAG-система на ChromaDB и OpenAI API с кешем
ответов и подробным замером времени каждого этапа обработки запроса.

Ассистент отвечает на вопросы по локальной базе знаний. Повторные вопросы
отдаются из кеша примерно в 28 000 раз быстрее полного цикла. После каждого
ответа выводится, сколько времени ушло на поиск, на обращения к API и на
запись в кеш.

```
⏱  Время ответа: 2.88147 с
   ├─ проверка кеша        : 0.00010 с
   ├─ эмбеддинг запроса    : 0.48518 с
   ├─ поиск в ChromaDB     : 0.00173 с
   ├─ генерация ответа LLM : 2.39150 с
   └─ запись в кеш         : 0.00144 с
      прочее               : 0.00152 с
   🧾 Токены: 2005 на вход, 134 на ответ, 2139 всего
```

## Зачем этот проект

Он показывает не только как собрать RAG, но и где в нём на самом деле уходит
время и деньги. Разбивка по этапам печатается всегда, поэтому утверждения вроде
"кеш ускоряет ответы" перестают быть словами и превращаются в числа, которые
можно посмотреть на своей машине.

Проект годится как отправная точка для своего ассистента по документации,
внутренней базе знаний или FAQ. Код прокомментирован построчно, настройки
вынесены в один файл, промпты лежат отдельно от кода.

## Как это работает

```
вопрос пользователя
      │
      ▼
 проверка кеша ──── найдено ──▶ готовый ответ (0.0001 с)
      │
   не найдено
      │
      ▼
 эмбеддинг запроса (OpenAI API)
      │
      ▼
 поиск в ChromaDB ── фильтр по источнику (опционально)
      │
      ▼
 сборка контекста из найденных фрагментов
      │
      ▼
 генерация ответа (OpenAI API)
      │
      ▼
 запись в кеш ──▶ ответ пользователю
```

## Быстрый старт

Нужен Python 3.10 или новее и ключ OpenAI API.

```bash
git clone https://github.com/yagitpa/PEr07_RAG_optimizer_with_cache
cd PEr07_RAG_optimizer_with_cache

python -m venv venv

# Windows
.\venv\Scripts\activate
# macOS / Linux
source venv/bin/activate

pip install -r requirements.txt
```

Скопируйте `env.example` в `.env` и впишите ключ:

```
OPENAI_API_KEY=sk-...
```

Запуск:

```bash
python main.py
```

При первом запуске база пуста, поэтому проект автоматически проиндексирует
три тестовых документа: 9 чанков, несколько сотых цента на эмбеддинги. Дальше
база берётся с диска.

> Строку `OPENAI_BASE_URL` в `.env` оставьте закомментированной, если работаете
> напрямую с OpenAI. Подробности ниже, в разделе про подводные камни.

## Режимы работы

При запуске проект спрашивает режим.

| Режим | Что делает |
|---|---|
| 1. Интерактивный | Вопросы вводите вы, доступны служебные команды |
| 2. Демонстрационный | Прогоняет вопросы из `DEMO_QUESTIONS`, последним повторяет первый, чтобы показать работу кеша |
| 3. Замеры | Каждый вопрос задаётся дважды, мимо кеша и из кеша, в конце выводится таблица со временем и ускорением |

Режим замеров перед первым прогоном удаляет записи кеша по своим вопросам:
иначе замер полного цикла будет нечестным.

## Команды интерактивного режима

| Команда | Действие |
|---|---|
| `help` | Список команд |
| `stats` | Состояние системы, попадания в кеш, текущий top_k |
| `cache` | Размер кеша и статистика за сессию |
| `clear_cache` | Очистить кеш |
| `sources` | Источники в базе и число чанков в каждом |
| `filter Python` | Искать только по источникам, содержащим эту подстроку в имени |
| `filter off` | Снять фильтр |
| `topk 7` | Сменить top_k на время сессии |
| `reindex` | Очистить базу и проиндексировать документы заново |
| `exit` | Выход |

## Настройки

Всё настраивается через `.env`. Значения по умолчанию лежат в блоке `DEFAULT_*`
файла `config.py`, переменная окружения их переопределяет. Некорректные значения
отклоняются при запуске с понятным текстом, а не ломают работу посередине.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `OPENAI_API_KEY` | - | Ключ API, обязателен |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | Адрес API, менять только для прокси |
| `LLM_MODEL` | `gpt-3.5-turbo` | Модель для генерации ответов |
| `LLM_TEMPERATURE` | `0.7` | Разброс ответов, от 0 до 2 |
| `LLM_MAX_TOKENS` | `500` | Верхняя граница длины ответа |
| `EMBEDDING_MODEL` | `text-embedding-3-small` | Модель эмбеддингов |
| `CHROMA_PERSIST_DIR` | `./chroma_db` | Папка с базой |
| `CHROMA_COLLECTION` | `rag_documents` | Имя коллекции |
| `CHROMA_DISTANCE` | `cosine` | Метрика расстояния |
| `CHUNK_SIZE` | `500` | Размер чанка в символах |
| `CHUNK_OVERLAP` | `50` | Перекрытие чанков |
| `TOP_K` | `3` | Сколько фрагментов уходит в контекст |
| `SOURCE_FILTER` | пусто | Ограничение поиска источниками по подстроке |
| `CACHE_FILE` | `cache.json` | Файл кеша |
| `CACHE_ENABLED` | `true` | Выключается, чтобы замерить время без кеша |
| `CACHE_KEY_INCLUDES_PARAMS` | `true` | Учитывать параметры в ключе кеша |
| `TIME_PRECISION` | `5` | Знаков после запятой во времени |
| `SHOW_TIMING_BREAKDOWN` | `true` | Показывать разбивку по этапам |
| `DEMO_QUESTIONS` | три вопроса | Список для демо-режима, разделитель `\|` |

Полный список с комментариями лежит в `env.example`.

## Как добавить свои документы

Откройте `embeddings.py`, найдите функцию `get_sample_documents()` и замените
её содержимое своими текстами:

```python
return [
    ("Название документа", "Текст документа..."),
    ("Другой документ", "Ещё текст..."),
]
```

Затем удалите папку `chroma_db` или выполните команду `reindex` в интерактивном
режиме. После смены документов кеш стоит очистить командой `clear_cache`: он не
знает, что база изменилась, и продолжит отдавать старые ответы.

## Результаты замеров

Данные реального прогона: `gpt-3.5-turbo`, температура 0.2, база из 9 чанков.

Куда уходит время при полном цикле:

| Этап | Доля общего времени |
|---|---|
| Генерация ответа моделью | 83-90 % |
| Создание эмбеддинга запроса | 10-17 % |
| Поиск в ChromaDB | 0.04-0.21 % |

Почти всё время ответа - это ожидание чужого сервера по сети. Локальный
векторный поиск на такой базе узким местом не является, поэтому оптимизировать
надо число обращений к API, а не скорость поиска.

Что даёт кеш:

| Вопрос | Полный цикл | Из кеша | Ускорение |
|---|---|---|---|
| Привет, что ты умеешь? | 3.20577 с | 0.00016 с | в 20 149 раз |
| Что такое RAG? | 2.24502 с | 0.00009 с | в 26 258 раз |
| Что такое ИИ? | 3.75593 с | 0.00009 с | в 41 048 раз |

Кеш хранится в словаре в оперативной памяти, файл `cache.json` читается один
раз при старте. Поэтому попадание стоит десятые доли миллисекунды.

Что даёт рост TOP_K с 3 до 7 на базе из 9 чанков:

| Показатель | TOP_K=3 | TOP_K=7 |
|---|---|---|
| Токенов на вход | 2010 | 2777 |
| Похожесть нижнего фрагмента | 0.301 | 0.202 |
| Содержание ответа | - | не изменилось |

Плюс 38 % расходов и ноль изменений в ответе: добавленные фрагменты имели
похожесть около 0.2 и в ответ не попали. На базе из тысяч документов та же
семёрка была бы разумной, на девяти чанках она означает "взять почти всё".

## Подводные камни, на которые проект уже наступил

**Пустой `OPENAI_BASE_URL` ломает всё.** Строка `OPENAI_BASE_URL=` в `.env`
задаёт переменную окружения с пустым значением. Библиотека `openai` читает эту
переменную самостоятельно и пустую строку принимает за адрес, после чего запрос
уходит без протокола:

```
httpx.UnsupportedProtocol: Request URL is missing an 'http://' or 'https://' protocol
```

Поэтому адрес всегда передаётся в клиент явно из `config.py`, а значение без
`http://` или `https://` отклоняется при запуске.

**Метрика ChromaDB по умолчанию не cosine.** Если создать коллекцию без явного
указания метрики, ChromaDB возьмёт L2, где расстояние не ограничено сверху.
Показатель похожести `1 - расстояние` при этом теряет смысл. Здесь метрика
задаётся явно, а при несовпадении с уже созданной коллекцией выводится
предупреждение: сменить метрику существующей коллекции нельзя, нужна
переиндексация.

**Кеш по одному только тексту вопроса мешает экспериментам.** Если ключ считать
только от вопроса, то после смены `TOP_K` тот же вопрос вернёт старый ответ,
посчитанный при старых настройках. Здесь в ключ входит подпись параметров:
модель, температура, лимит токенов, модель эмбеддингов, top_k и фильтр. Смена
любого из них автоматически даёт промах кеша.

**`str.format()` падает на документах с фигурными скобками.** Подстановка в
шаблоны промптов идёт по плейсхолдерам `{{ИМЯ}}` через замену строк. После
подстановки загрузчик проверяет, что незаполненных плейсхолдеров не осталось.

## Системный промпт

Системный промпт сгенерирован моделью с помощью скилла `/ai-instruction-design`. ([GitHub](https://github.com/yagitpa/ai-instruction-design))

Промпты лежат в `prompts/` отдельными файлами: их правят чаще, чем логику, и
правка не должна требовать чтения Python-кода.

Правила поведения находятся в системном сообщении, а сообщение пользователя
несёт только данные - контекст и вопрос. Правила размечены по силе
(`ИНВАРИАНТ`, `ТРЕБОВАНИЕ`, `ПО УМОЛЧАНИЮ`, `ЗАПРЕТ`, `ФАКТ СРЕДЫ`), описаны
пять взаимоисключающих маршрутов с порядком проверки:

1. Контекст отвечает на вопрос полностью.
2. Контекст отвечает частично.
3. Контекст не относится к вопросу или пуст.
4. Вопрос вообще не про базу знаний: приветствие, вопрос о возможностях.
5. Запасной вариант.

Отдельно оговорено, что содержимое контекста - это данные, а не инструкции.
Если внутри фрагмента базы знаний встретится указание сменить роль или отменить
правила, модель должна его не выполнять, а отметить в ответе. Для локальной
базы из трёх файлов это избыточно, но как только в базу попадут документы из
внешних источников, риск становится реальным.

## Известные ограничения

- Кеш не знает об изменениях базы знаний. После переиндексации его нужно чистить
  вручную командой `clear_cache`.
- Порога релевантности нет: в контекст уходят top_k фрагментов независимо от
  того, насколько они подходят. На вопросах не по теме это тратит лишние токены.
- Чанкинг простой, по числу символов, без учёта границ предложений и абзацев.
- Модель по умолчанию `gpt-3.5-turbo`, как в исходном учебном проекте. Она
  устарела; поменять можно одной строкой в `.env`.
- Ключ API нужен и для эмбеддингов, и для генерации. Полностью офлайн проект не
  работает.

## Направления доработки

- Порог релевантности: не собирать контекст, если лучший фрагмент ниже порога.
- Версия базы знаний в подписи ключа кеша, чтобы переиндексация сама
  инвалидировала старые ответы.
- Умный сплиттинг по границам абзацев вместо резки по символам.
- Ограничение размера кеша и вытеснение старых записей.
- Подключение интерфейса: Telegram-бот или веб-страница.

метаданные и учитывает параметры в ключе, добавлены фильтр по источникам и
режим замеров.
